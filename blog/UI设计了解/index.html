    维度 网页设计 网页开发

    产出物 设计稿、原型图、UI规范、动效说明 可运行的网站/应用、API接口
    关注点 美不美、好不好用、流不流畅 能不能跑、快不快、稳不稳定
    关键角色 UI设计师、UX设计师、交互设计师 前端工程师、后端工程师、全栈工程师

    网页设计方法

    1. 用户中心设计 (UCD - User-Centered Design)
    • 核心理念：从用户需求出发，让用户参与整个设计过程
    • 流程：调研用户 → 定义需求 → 设计原型 → 测试验证 → 迭代优化
    • 场景：追求用户体验的产品（几乎所有现代网站）
    1. 响应式设计 (Responsive Design)
    • 核心理念：一套代码适配所有屏幕尺寸
    • 关键技术：流体网格、弹性图片、媒体查询
    • 场景：需要同时在手机、平板、电脑上使用的网站
    1. 移动优先设计 (Mobile First Design)
    • 核心理念：先设计手机版，再逐步增强到桌面版
    • 原因：手机用户最多、屏幕限制最严、性能最宝贵
    • 场景：移动端流量占比高的产品（电商、社交、资讯）
    1. 极简主义设计 (Minimalist Design)
    • 核心理念：少即是多，去掉一切不必要的元素
    • 特征：大量留白、有限配色、简洁字体、扁平图标
    • 场景：品牌官网、作品集、Apple/Google类产品
    1. 材质设计 (Material Design) —— Google
    • 核心理念：模拟纸张和墨水的物理特性，用层级表达深度
    • 特征：卡片、阴影、动效、FAB按钮（悬浮操作按钮）
    • 场景：Android应用、Google系产品
    1. 人机界面指南 (HIG - Human Interface Guidelines) —— Apple
    • 核心理念：清晰、遵从、深度，强调内容本身
    • 特征：半透明毛玻璃效果、大标题、边缘滑动返回
    • 场景：iOS/macOS应用、Apple官网
    1. 原子设计 (Atomic Design)
    • 核心理念：像化学元素一样，从最小单元组合成页面
    • 层级：原子（按钮）→ 分子（搜索框+按钮）→ 有机物（导航栏）→ 模板 → 页面
    • 场景：需要建立统一组件库的大型项目
    1. 以内容为中心的设计 (Content-First Design)
    • 核心理念：先确定内容和信息架构，再设计视觉
    • 场景：博客、新闻网站、文档站、在线课程
    1. 无障碍设计 (Accessibility / A11y)
    • 核心理念：让残障人士（视障、听障、行动障碍）也能正常使用
    • 关键技术：语义化HTML、高对比度、键盘导航、屏幕阅读器支持
    • 场景：政府网站、公共服务、追求普适性的商业网站

    网页开发方法

    1. 传统开发方法
    方法 核心特征 优缺点 现状
    多页应用 (MPA) 每次跳转都重新加载整个页面 SEO好、首屏快；但页面闪烁、体验割裂 博客、官网仍用
    渐进增强 先保证基础功能在所有浏览器运行，再叠加高级特性 兼容性极好；开发成本高 政府、银行网站
    优雅降级 先为现代浏览器开发全功能版，再为旧浏览器减配 开发快；旧浏览器体验差 渐被淘汰
    1. 现代前端开发方法
    方法 核心特征 代表技术 场景
    单页应用 (SPA) 一次加载，局部刷新，前端控制路由 React、Vue、Angular Gmail、Figma、Spotify Web
    服务端渲染 (SSR) 在服务器生成完整HTML再发送 Next.js、Nuxt.js、Remix 电商、新闻、需要SEO的SPA
    静态站点生成 (SSG) 构建时生成静态HTML，部署到CDN Hugo、Hexo、Astro、Jekyll 博客、文档站、作品集
    微前端 将前端应用拆分成独立子应用，组合成一个整体 qiankun、Module Federation 大型企业级应用（多个团队协作）
    岛屿架构 页面大部分是静态HTML，只有少数交互区域是动态的 Astro、Qwik 内容型网站（博客、营销页）
    1. 开发模式/方法论
    方法 核心流程 适用场景
    敏捷开发 迭代推进、快速交付、持续反馈 大多数互联网产品
    Scrum 固定周期（1-4周）冲刺，每日站会，Sprint评审 产品快速迭代
    看板 可视化任务流，限制并行任务数 运维、维护类项目
    极限编程 (XP) 测试驱动开发、结对编程、持续集成 需求变化频繁、质量要求高的项目
    1. 工程化方法
    方法 核心内容 工具示例
    模块化 将代码拆分成独立模块 ES Modules、CommonJS、AMD
    组件化 封装UI和逻辑为可复用的组件 React/Vue组件、Web Components
    构建自动化 自动编译、打包、压缩、热更新 Webpack、Vite、Parcel、Rollup
    版本控制 协作开发、代码追溯 Git、SVN
    持续集成/持续部署 自动测试、自动部署 GitHub Actions、GitLab CI、Jenkins
    响应式编程 用数据流处理异步事件 RxJS、Signals（Vue/Solid）

    协作方法

    方法 作用 工具/实践
    设计系统 统一设计和开发的组件库，保证一致性 Ant Design、Material UI、Arco Design
    设计稿交付 设计师产出 → 开发者实现 Figma Dev Mode、Zeplin、蓝湖
    设计令牌 (Design Tokens) 将设计变量（颜色、字体、间距）转为代码变量 Style Dictionary、CSS变量
    Storybook 在开发环境中独立开发和测试UI组件 React/Vue/Angular组件库
    Figma to Code 自动将设计稿生成代码 Figma插件（Anima、Locofy）
    AB测试 同时上线多个版本，用数据决定哪个好 Google Optimize、VWO

    尺寸单位

    一、绝对单位 (Absolute Lengths)

    这类单位是固定值，不会因为屏幕或父元素的变化而改变。通常用于打印样式或需要精确控制物理尺寸的场景。

    单位 英文全称 含义/来源 换算关系 使用场景
    px Pixel 图像显示的基本单位，源自”picture element” 屏幕最小单位，CSS绝对长度基准 屏幕显示（边框、阴影、小图标）
    pt Point 印刷业传统单位 1/72 英寸 传统印刷、Word排版；网页中一般不用
    pc Pica 印刷业传统单位 1/6 英寸 (12pt) 印刷排版，Web基本不用
    cm Centimeter 厘米，公制长度单位 1in = 2.54cm 屏幕显示不准，偶尔用于打印样式
    mm Millimeter 毫米，公制长度单位 10mm = 1cm 屏幕显示不准，偶尔用于打印样式
    in Inch 英寸，英制长度单位 1in = 2.54cm 屏幕显示不准，偶尔用于打印样式

    二、相对单位 (Relative Lengths)

    这类单位是相对的，会根据某个基准值（父元素、视口、根元素）动态变化，是实现响应式设计和无障碍访问的核心。

    单位 英文全称 含义/来源 换算关系 使用场景
    rem Root EM 相对于根元素字体大小（EM指字母M宽度） 根元素(<html>)的字体大小 全局字体、间距、宽度；支持浏览器字号缩放
    em EM（排版术语） 相对于当前元素字体大小 当前元素的字体大小 相对于自身字体缩进的边距(margin/padding)
    % Percent 百分比 父元素的同属性值 流式布局、栅格系统、弹性图片
    vw Viewport Width 视口宽度百分比 视口宽度的1% 全屏容器、大标题、视口适配
    vh Viewport Height 视口高度百分比 视口高度的1% 全屏滚动、首屏页脚、移动端全屏弹窗
    vmin Viewport Minimum 视口宽度和高度中较小者的百分比 vw和vh中较小者 确保元素在横竖屏切换时都能完整显示
    vmax Viewport Maximum 视口宽度和高度中较大者的百分比 vw和vh中较大者 超大背景装饰元素
    ex x-height 当前字体中字母”x”的高度 当前字体中字母x的高度 特殊垂直对齐，使用较少
    ch Character width 当前字体中数字”0”的宽度 当前字体中数字0的宽度 限制文本行宽（如max-width: 60ch）

    三、移动端/跨平台专用单位

    这类单位更多出现在移动端开发、React Native、Flutter 或 微信小程序中。

    单位 英文全称 含义/原理 所属框架/平台 使用场景
    dp / dip Density-Independent Pixel 密度无关像素。160dpi屏幕上1dp=1px，高密度屏幕自动放大 Android 原生 / React Native 所有尺寸（宽高、边距、圆角）
    sp Scale-independent Pixel 缩放无关像素。类似dp，但额外缩放用户字体偏好 Android 原生 文字大小（保证视障用户可读）
    rpx Responsive Pixel 响应式像素。屏幕宽固定为750rpx，自动换算 微信小程序 所有尺寸（手机端完美适配）
    pt (iOS) Point 逻辑点单位。1pt = 1/72英寸（非Retina屏1pt=1px） iOS (UIKit/SwiftUI) iOS界面设计稿标注和开发

    四、特殊功能单位 (CSS 函数/高级单位)

    单位/函数 英文全称 含义 作用 使用场景
    fr Fraction 分数单位 CSS Grid中的剩余空间分数 grid-template-columns: 1fr 2fr（比例分配宽度）
    min() Minimum function 取最小值函数 取两个值中的较小值 让容器响应式缩小但有上限：width: min(100%, 600px)
    max() Maximum function 取最大值函数 取两个值中的较大值 让容器响应式放大但有下限：width: max(50%, 300px)
    clamp() Clamp function 钳位函数 限制在一个区间内 响应式字体：font-size: clamp(12px, 4vw, 24px)
    calc() Calculate function 计算函数 混合单位计算 width: calc(100% - 20px)（混合百分比和绝对单位）

    记忆口诀：

    屏幕边框用 px，全局字体找 rem，父级参照用 %，视口比例 vw/vh，安卓尺寸用 dp，iOS 布局靠 pt，比例布局上 fr。
